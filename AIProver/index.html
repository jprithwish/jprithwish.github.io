AIProver: Agentic Auto-Formalization of Mathematical Research via Certificate-Driven Evolving Harness

AIProver is an agentic framework for autonomous proof auto-formalization and proof synthesis: it translates natural-language theorems and proofs into Lean and closes the proofs. It jointly post-trains a 119B open-weight language model and evolves the tool-calling harness around it. Verifiers for type correctness, proof completeness and semantic correctness return graded rewards and diagnostic certificates, which drive reinforcement learning via symbolic feedback and HarnessEvolve, a certificate-driven evolutionary search over the whole harness control flow that re-tailors the harness to the updated model.

On LoCoBench, a new 58.9k-instance benchmark of research-level mathematics, AIProver lifts semantic correctness over its Leanstral-1.5 base from 15.7% to 36.7% and outperforms every other open-weight system and Aristotle. As a Claude Code and Codex skill, it lifts the hosts from 41.9% and 34.1% to 79.8% and 62.4%, more accurate and cheaper than Numina-Lean-Agent and OpenGauss in the same role.

01

Overview

Proof auto-formalization translates natural-language (NL) theorems and proofs into a formal language (FL) such as Lean, where a trusted kernel checks every step. AI agents have begun to do this at research scale, but the systems that succeed share limitations: they run on frontier models at frontier prices, lean on mathematicians in the loop, use hand-built harnesses that are never adapted to the model inside them, and treat compilation as success even when the formal statement no longer means what the paper said.

Same base model, post-trained inside an evolved harness. Leanstral-1.5 in the seed harness proves 15.7% of LoCoBench-Val theorems semantically correctly. After HarnessEvolve and interleaved RLSF it proves 36.7%, more than any other open-weight system and more than the closed-source Aristotle.

Four challenges stand between current agents and research-level auto-formalization. Semantic alignment: a decoder trained on language modelling alone treats an NL proof and its Lean counterpart as two unrelated strings. Faithful supervision: a binary compiles/does-not-compile signal hides partial progress and rewards vacuous statements. Research-level data: no dataset offers NL theorem–proof pairs at scale beyond competition mathematics. A model-tailored harness: expert-written harnesses are fixed, while the model inside them keeps changing.

AIProver answers each in turn. A semantic alignment model (SAM) is fine-tuned so that the NL and FL views of a theorem land at the same point of a shared space. A graded reward ladder with diagnostic certificates lets reinforcement learning and harness search learn from partial success. LoCoBench supplies 58.9k research-level instances with an out-of-distribution validation split. And HarnessEvolve searches over the whole harness program with a coding agent as the mutator, keeping rejected designs as negative evidence so that later mutations steer away from what already failed.

Problem statement · Proof auto-formalization and proof synthesis (AFPS)

Given a natural-language theorem and proof ℳNL, produce a Lean theorem and proof ℳFL that compiles, is complete (no sorry, no extra axioms), and states the same theorem as the source.

Type correctness (TC)Lean accepts the file: every definition and tactic step resolves and the kernel type-checks the proof term.
Completeness (CP)Every goal is closed without a placeholder, and the proof uses no axioms beyond Lean’s standard ones.
Semantic correctness (SC)The formal statement is logically equivalent to the gold one, tested with an extended BEq+ that tries to prove each direction, so variable names, hypothesis order or lemma choice do not matter.
02

Method

Four components drive AIProver: two post-train the model, one evolves the harness, and one reward with certificates ties them together. Model and harness are updated in alternation, never at once, so each update sees the other’s latest state.

Model · cold start

Semantic Alignment Model (SAM)

A decoder-only LLM fine-tuned with low-rank adapters so that an NL theorem–proof and its Lean formalization are represented as the same mathematical object. Two forward passes give two views: the hidden state at a reserved [PRED] token after the NL text, and the final state of the Lean text alone. A contrastive loss pulls matched views together while the language-modelling loss keeps the model generative.

Effect. The cosine of matched NL–FL pairs rises from 0.11 to 0.75, and RLSF mostly keeps it (0.64). SAM is the aligned starting point from which both RLSF and HarnessEvolve proceed.

Harness · search

HarnessEvolve

Evolves the harness while the model is frozen. A search memory is a tree rooted at the current harness; every evaluated harness is kept, accepted or rejected, with its fitness, per-instance rewards, certificates and the source diff that produced it. Each round, a UCB rule picks a parent, a coding agent rewrites it into a child guided by the certificates and by the rejected designs nearby, and the child is scored on the training split.

Negative evidence. As conflict-driven clause learning does in SAT solvers, the mutator conditions on every refuted design, not only on the parent, so the search stops revisiting dead ends.

Model · post-training

Agentic RLSF

Reinforcement learning via symbolic feedback for multi-turn agents. An episode is one run of the agent inside the frozen new harness: reasoning, tool calls and observations, turn after turn. Only the Lean file written at the end is rewarded, by sound symbolic tools (the Lean kernel and BEq+) instead of a learned reward model. Optimized with GRPO over groups of rollouts, with gradients only on the tokens the model generated.

Why a ladder, not a bit. With outcome supervision, a binary compile reward leaves almost every rollout at zero. The graded ladder below gives credit for ill-typed, incomplete and semantically-off proofs in proportion to how close they came.

Reward ladder one reward and one certificate per instance, shared by RLSF and HarnessEvolve

OutcomeTCCPSCReward r
No answer–––0
Ill-typed✗––0.05
Incomplete proof✓✗vSC0.15 + 0.35 vSC
Complete proof✓✓vSC0.30 + 0.60 vSC
Solved✓✓✓1 − 0.10 (1 − vLF)

vSC ∈ {0, 0.5, 1} is the semantic-correctness verdict of BEq+ (one direction or both); vLF is a length-fidelity term that penalizes proofs far shorter or longer than the gold one. The certificate carries Lean’s diagnostics, the failed goals and the equivalence verdict, so a mutator or a policy can see why a candidate scored as it did.

The co-evolution loop bootstrap, then K interleaved and gated rounds

Bootstrap the harness

HarnessEvolve takes the seed harness ℋ0 (Mistral’s Vibe with Lean LSP tools) to ℋ1 under the base model ℳ0.

Bootstrap the model

SAM fine-tuning turns ℳ0 into ℳ1 on the labelled NL–Lean pairs of LoCoBench-Train.

Round i: evolve

With ℳi frozen, HarnessEvolve re-tailors ℋi → ℋi+1 on its own training subset.

Round i: post-train

With ℋi+1 frozen, RLSF post-trains ℳi → ℳi+1 on a disjoint subset. The new pair is kept only if held-out fitness improves; otherwise it is rolled back.

03

LoCoBench

A benchmark of 58.9k instances for proof auto-formalization of research-level mathematics in three fields: algebraic structures (ring and group theory), foundations, logic & complexity (set theory, logic, computability, model theory, bounded arithmetic) and number theory. No existing research-level dataset offers NL theorem–proof pairs at this scale: ShadowBench has 178 examples and ArXivLean has no proofs.

18.8k labelled NL–Lean pairsFrom Mathlib and CSLib: 10.2k, 5.9k and 2.7k theorem+proof pairs for the three fields, each emitted as a standalone, type-checked .lean file after dependency analysis.
40.1k unlabelled NL–Mizar pairsFrom the Mizar Mathematical Library, published in Formalized Mathematics: 18.3k, 8.0k and 13.8k pairs, one standalone .miz file per theorem. Mizar has no Lean counterpart anywhere online.
771 validation instancesThe 100 longest-proof Mizar theorems in each of seven domains, plus the 71 theorems of a research-level bounded-arithmetic textbook. Out of distribution by construction: nothing to retrieve or imitate.
39 systems comparedAFPS models, AFPS agents, foundation models and coding agents, evaluated at pass@4 under three nested criteria: TC, TC+SC with or without sorry, and TC+SC with full proofs.

Informalization. LLMs informalize (FL to NL) far more accurately than they formalize. Each .lean and .miz file is informalized by a coding agent (Claude Code with Opus 4.8) in a feedback loop with CriticLeanGPT, an NL–FL faithfulness judge, and revised until it passes.

Train/Val split. Mathlib and CSLib instances go to Train because their Lean is public and likely memorized. Val is drawn from Mizar and the textbook, whose theorem–proof pairs have no public Lean formalization; its instances have more auxiliary theorems and far longer natural-language text than Train or prior benchmarks. The remaining Mizar theorems join Train with Lean formalizations distilled from a teacher under verifier feedback: each must compile and pass the semantic check.

As a standalone agent. Every open-weight AFPS or foundation model stays below 3.9% TC+SC on LoCoBench-Val; AIProver raises this nearly tenfold to 36.7%. It outperforms frontier models and agents such as GPT-5.6-Sol (25.2%), Aristotle (18.4%) and Codex (34.1%); only Claude Code (41.9%) is higher. From the same Leanstral-1.5 base it outperforms OpenGauss on every field (36.7% vs. 21.5% overall), and its 67.0% on number theory is above Codex (62.0%) and Claude Code (57.0%).

As a skill for frontier coding agents. The host handles planning and decomposition; AIProver, a Lean-specialist sub-agent on local GPUs, handles Lean writing and proof search. AIProver adds 37.9 points to Claude Code and 28.3 to Codex, whereas Numina-Lean-Agent adds 30.6 and 10.4 and OpenGauss 12.4 and 7.8. The weaker host gains almost three times more from AIProver than from either prior agent, so the gain comes from AIProver rather than from the host.

Cost

Every cost is the sum of the frontier coding agent’s tokens at list prices, if any, and the GPU time that serves the open-weight model, if any, over the same 3,084 attempts (771 instances × 4). Standalone, AIProver and OpenGauss both run on local GPUs for $0.32 per attempt, yet AIProver reaches 36.7% against 21.5%. With Claude Code it reaches 79.8% at $1.55, against 72.5% at $2.03 for Numina-Lean-Agent and 54.3% at $1.80 for OpenGauss. With Codex it reaches 62.4% at $0.85, against 44.5% at $1.08 and 41.9% at $1.05. Offloading Lean work to a specialist sub-agent makes the host spend fewer tokens and gain accuracy at the same time.
